# 安全与扫描说明

## 扫描不会清理文件

Mac Sweep 的检查与目录分析不会移动或删除文件。目录大小与清理候选检查只读取文件元数据，不读取候选文件正文；识别已安装应用时另读取其应用标识文件及运行进程。所有操作在本机完成，无服务器、账户或遥测上传。扫描结果与清理记录只保留在当前应用会话，重新启动后需要再次检查。

目录占用分析可以查看你选定的目录，包括隐藏文件、代码项目和模型等内容。目录大小不会自动成为清理建议。右键手动移动是独立操作，只有用户确认后才执行。

## 哪些文件会成为清理候选

清理检查只从下列用户目录收集符合规则的旧文件，默认保留近 14 天内修改的文件。

| 位置 | 候选内容 | 默认选择 |
| --- | --- | --- |
| `~/Library/Caches` | 达到保留天数的旧缓存 | 建议项会勾选；已识别的开发运行时缓存及疑似残留需手动选择 |
| `~/Library/Logs` | 达到保留天数的旧日志 | 建议项会勾选 |
| 已知工具、浏览器、沙盒及应用缓存子路径 | npm、Cargo、Go、pip、uv、Homebrew、Xcode DerivedData 等旧缓存 | 手动选择；不扫描整个工具或应用数据目录 |
| `~/Downloads` | 旧 `.dmg`、`.pkg`、`.mpkg`、`.iso` 安装包 | 手动选择 |
| `~/Library/Preferences`、`Caches`、`Saved Application State` | 无法匹配常见应用目录的反向域名条目 | 疑似残留，手动选择 |
| `~/Library/Application Support` | 未匹配同标识或同开发者应用的反向域名文件夹 | 疑似残留，手动选择 |

检查范围的具体路径、参考来源和排除内容见 [清理规则](CLEANUP_RULES.md)。

Application Support 中的残留整目录候选还要求目录及全部子项达到保留天数、可完整读取且不含已识别的受保护内容。它可能包含数据库、设置、聊天记录和个人文件，必须在 Finder 中检查后再选择。

未匹配到应用仅是线索：应用可能改名、安装在其他目录，或由辅助程序生成数据。较旧缓存也可能仍被使用，建议先退出对应应用。已识别的 Playwright、pip、pnpm 等工具运行时缓存需要手动确认。

清理检查不遍历系统清理目录、废纸篓、Group Containers，也不遍历文稿、图片或代码项目的常规存储位置。Containers 仅检查非受保护应用的 Data/Library/Caches。Application Support 的新增缓存规则只检查明确的缓存子目录；浏览器仅检查白名单缓存位置。浏览历史、Cookie、密码、会话、数据库、游戏存档、模型和 Git 仓库内容会被保护；规则无法识别所有个人数据，应用残留目录中的其他文件仍需人工核实。下载目录里的普通 ZIP、文档与项目不会当作安装包。

应用另读取常见应用目录中的应用标识及运行进程，以减少残留误判。无法读取运行进程时，不会预先勾选任何候选，清理时也会保留项目并报告原因。

## 清理前还会再检查

每个清理请求只能引用最近一次检查中的项目 ID。清理前，应用重新检查允许目录、符号链接、文件身份、时间戳和目录内条目，并逐项更新对应应用的运行状态。检测到变化或关联应用正在运行时，会保留该项目。

检查与清理互斥，可以取消检查。验证与系统移动之间仍有很短的间隔，先退出对应应用可以减少文件变化。清理期间会暂时阻止常规关闭窗口和退出，以便完成文件移动；强制退出或系统关机仍可中断操作。

清理检查优先合并完整旧缓存分支，最多收集 10,000 项、访问 1,000,000 次或运行 180 秒。每个应用来源每类最多收集 500 项，达到后继续检查其他应用；不会因单个应用的小文件数量多而停止全部检查。遇到权限不足或达到上限时会明确显示部分结果，原因可从检查提示中展开查看。

主列表先按应用与用途合并候选，每页最多显示 30 组；同一组不会因为候选数量较多而重复出现在不同页。文件详情按需展开，每页最多显示 100 项。组复选框选择当前筛选下该组的全部项目，包含其他详情页中的项目；搜索、筛选和切换页码不会取消已有选择。需要你确认的组必须先展开查看，才能选择整组。确认清理时，应用会汇总全部已选项目，包括当前筛选中未显示的项目。

## 废纸篓与恢复

清理逐项调用 macOS 废纸篓接口，不执行永久删除。失败项目会保留原文件和选择，并显示原因。清理页面的字节数是已处理候选的大小，不是立即释放的磁盘容量。

文件进入废纸篓后仍占空间。确认不再需要后，请自行在 Finder 清空废纸篓；清空后不能通过本应用恢复。需要恢复时，可在 Finder 中把文件从废纸篓拖回原目录，原路径可在本次会话的清理记录中查看。应用不提供自动恢复按钮。

清理记录关闭窗口或刷新后消失；清除记录不会清空废纸篓。

清理结果在清理页底部显示，移动记录按需展开。只有原生回执确认的项目才计入已移动数量；未完成项目保留选择，详情保留原因。系统移动后的验证也可能失败，因此未完成不保证原路径上的文件仍存在；结果未确认时，应在 Finder 检查状态后再操作。

## 收藏目录

收藏只保存目录位置，不保存目录扫描或清理结果。配置位于本机 `~/Library/Application Support/com.dogeow.mac-sweep/favorites.json`，关闭应用后仍保留；取消收藏只修改此配置，不移动或删除文件夹。

新增收藏只能引用已注册分析中的真实目录 ID，并检查当前路径及文件身份。点击收藏时，应用只根据已保存的收藏 ID 验证目录位置；有可用分析时复用统计或读取直属列表，无可用统计时也只读取直属列表，未统计的目录大小保持未知。完整分析需用户点击触发。目录被移走、删除或无法访问时，不会自动删掉收藏，也不会通过收藏执行清理。

收藏配置最多保留 64 个目录、64 KiB 文件，采用串行原子写入及仅当前用户可读写的权限。读取损坏或失败时会保留原配置并拒绝覆盖，不把读取失败当成空收藏。启动读取收藏不会遍历这些目录，也不会上传配置。

## 右键手动整理

右键菜单只引用当前已注册分析中的项目 ID，不接受任意删除路径。确认会显示原位置和已有大小；整个目录移动包含尚未展开或统计的子项，不等同于仅移动清理建议中的候选。移动前重新校验当前文件身份、来源范围和路径祖先，再调用系统废纸篓接口。用户主目录、标准顶层用户文件夹、系统目录、密钥与废纸篓位置不允许从此菜单移动，保护名单对 ASCII 大小写别名同样适用。

手动整理不永久删除文件、不自动清空废纸篓，不保证已有统计就是当前可释放大小。移动结果未确认时，在 Finder 检查原位置与废纸篓后再操作。校验与系统请求之间仍可能发生文件变化。

## 文件夹大小的含义

扫描使用常驻有界读取线程池和 macOS 批量元数据接口，仍保留云盘占位、硬链接、目录变化、跨卷和取消规则。批量读取前在线程内关闭自动下载占位内容的策略，结束后恢复原策略；无法安全取得元数据的项目仍标为部分结果。

进度条是按实际已发现、已处理的遍历工作分配预算所得的估计，不是精确文件总数或磁盘覆盖率。同一会话再次分析相同目录时，优先参考上次已结束扫描实际读取的文件数（最多 16 个目录的统计数）；这不是当前目录文件清单，也不会保存到磁盘。数量超过参考值时退回重新估算，取消或失败的扫描不成为参考。当前目录用同一个读取器有界枚举后分配工作进度，深层目录不再逐层压低预算；普通深层读取器最多为进度预取 1,024 条，超过时保留完整读取流并暂时显示未知估算，不截断扫描。已由受保护读取器完整返回的缓冲继续复用。时间流逝不会自动提升百分比。当前轮遍历未结束时不会显示 100%；正常返回部分结果也可以表示本轮已经结束，但原有未读取提示会继续保留。取消和失败不显示完成。预计剩余时间按实际进度变化和用时估算，采用近期速度与整体速度，并限制短分支造成的剧烈变化。计时器只倒数预计时间；目录规模未知、等待系统响应、长时间没有进度变化或预测到期时显示重新估算，不把倒计时到期当成完成。百分比与倒计时都不是磁盘容量比例或精确文件总数。

目录大小按已分配块统计，包括目录和符号链接自身的占用，不追踪子项符号链接的目标，也不跨到其他挂载卷。同一次目录扫描中，普通文件的硬链接按设备与 inode 去重：占用只计入首次读取的链接，其他链接仍计入文件条目数量。单独重新分析某个子目录时，硬链接的占用归属可能与整盘扫描不同。

云盘的在线占位文件或目录通过 macOS 元数据标记识别。分析会跳过未下载内容，不为扫描主动下载，也不会把云端显示的逻辑大小加入本机文件块统计；占位自身已经分配的本机块仍计入统计。不会按云盘提供方名称跳过整个目录，可访问的本地缓存文件仍会统计。结果单独记录在线占位位置数量，这不代表云端文件总数或已下载文件数。

APFS 克隆文件具有不同 inode，其共享块无法通过这套文件元数据统计精确去重；文件块统计可能因此高于所选卷的系统物理占用。应用会明确提示计量差异，不计算虚假的正差额，也不会把占用图显示成所有系统空间都已经定位。压缩、共享块、快照等都可能影响实际可释放空间。

目录分析不设全局运行时长或项目数量截止，不会在 300 秒或 200 万个条目时停止。仍保留 256 层的安全遍历深度。为限制界面与展示树的内存使用，结果保留前三层、每目录最大的 300 个子项，并以 15,000 个展示节点为展开预算；这些展示限制不截断目录大小的统计。未展示项目的已读取大小仍计入总数。完整分析同时在内存保留最多 20,000 个较大目录的大小摘要，不保存所有文件的路径；目录摘要索引由同一来源的浏览报告共享。进入深层目录时只读取直属条目并复用已有摘要，不自动递归重算；未保留摘要的大小显示为「待分析」，完整更新需手动触发。

对用户目录中的 `Desktop`、`Documents`、`Downloads`、`Music`、`Movies`、`Pictures`、`Library` 及其全部子目录，每个目录的直属条目枚举单独等待最多 10 秒；`/System/Volumes/Data/Users/…` 下对应位置采用同样规则。这些个人文件和应用数据区域涵盖 Containers 与 Group Containers。它只限制这些受保护目录树中的系统枚举调用，不设置整个磁盘的遍历截止；用户目录直属的 `Code`、`go`、`.cargo` 等其他位置及 `/Applications` 仍按普通方式流式遍历。

若受保护目录的系统枚举调用未返回，应用将该处标为部分结果并继续其他目录。进程最多保留 4 个尚未返回的读取工作线程；达到数量上限时跳过新的受保护枚举，避免反复扫描持续堆积线程。每个受保护目录的条目缓冲上限为 100,000 个，超出时会显示部分统计提示。目录浏览遇到枚举超时或线程限额时，仅从来源摘要中取出确切的直属子目录，不追加文件系统读取，不生成文件条目；保留原统计与目录身份，最多展示 300 项，并明确标为部分列表。来源缓存未保留的目录与文件可能无法显示，不能把该列表当成实时完整内容。

停止分析、读取失败、目录变化、达到安全深度、需要跳过的云盘在线占位目录、受保护枚举未响应或跨卷跳过时会标为部分结果，未知文件大小不会计入已定位文件。结果记录读取失败、权限不足、跨卷跳过、扫描期间变化、深度限制、云盘在线占位及受保护目录未读取的位置数量。受保护目录未读取的汇总包含枚举超时和等待线程达到限额。具体提示按需展开，不把扫描结束等同于读取全部文件。后端在当前会话分别保留最近 4 份完整分析和 128 份目录浏览供导航与 Finder 定位；更旧的结果会提示过期。目录浏览只能使用当前已注册分析内的目录 ID，并验证原目录设备、inode 及来源范围；不会把浏览的虚拟节点作为清理目标。已有大小带来源统计时间，打开耗时与完整分析耗时分别展示。

进入缓存目录或请求 Finder 定位前，应用检查记录中的项目是否仍存在、设备与 inode 是否一致、路径祖先是否仍解析到原位置。移动、删除或替换时，失效条目会从当前显示中移除，并尝试浅层刷新可用目录；权限失败不会当作删除。已知失效项目不会从旧占用总数直接扣减，旧统计会标为需更新。路径校验与系统请求之间仍可能发生文件变化，这不是文件系统快照。

## 整盘空间如何对照

选择卷根目录时，应用另外读取 macOS 的磁盘容量信息。APFS 容量及当前卷、其他卷的物理占用优先使用 macOS 自带 `diskutil` 返回的容量字段；无法取得完整信息时回退到 `statvfs`，并提示不能细分的部分。容量元数据在目录扫描后单独读取，磁盘活动也可能让两次计量的时间点不同。

- **系统已用**：系统报告的 APFS 容器总容量减可用空间；非 APFS 使用所在文件系统的容量信息。
- **已定位文件**：本次目录遍历能读取的文件块占用，包含被展示限制省略的已读取项目。
- **其他 APFS 卷**：系统报告的同一容器中其他卷的物理占用，无法可靠细分时不显示具体大小。
- **未归到文件夹的空间**：系统已用减已定位文件和已知其他卷占用后的非负差额。它可能包含访问受限文件、快照、容器或文件系统开销；其他卷无法细分时也可能包含在内，不能把整个差额归因于隐藏文件。

当文件块统计超过所选卷的物理占用时，应用显示计量差异并省略未定位差额。占用图继续展示已定位文件的目录分布，不把未定位空间或其他 APFS 卷伪造为文件夹。两条系统统计行只用于解释空间，不带文件 ID、Finder 定位或清理操作。进入普通子目录后，不添加整盘统计行。

建议清理大小仅统计符合清理规则的候选，与目录总大小及系统已用独立。系统统计行、未知差额和完整磁盘容量都不能用作清理目标，也不能当作可立即释放容量。

## macOS 权限与发布包

读取「下载」等目录时 macOS 可能询问权限。受保护目录无法读取时不会计入已定位文件，应用会显示部分结果。「查看访问权限」仅通过固定的系统设置链接打开完全磁盘访问权限页面；不会自动开启权限、修改隐私数据库或请求管理员扫描。

需要更完整的分析时，由你在系统设置 → 隐私与安全性 → 完全磁盘访问权限中添加并允许 Mac Sweep，再重新打开应用、重新扫描。权限变更不补充已有结果；即使开启权限，文件所有者、POSIX 权限或其他系统保护仍可能阻止访问，也不承诺能读取其他挂载卷、快照或所有系统内容。应用不会为补足这些结果自动改权或启用管理员扫描。

当前发布包面向 Apple Silicon Mac，最低系统版本为 macOS 12，使用本地 ad hoc 签名，没有 Apple Developer ID 签名或公证。macOS 可能阻止打开下载的应用；也可以按 README 从源码构建。应用不要求关闭系统安全检查。
